# 09-paid-diagnosis-questions.md — 有料診断 質問・ロジック定義（案）

## このセクションの目的

有料 IT・DX 現状診断（BIZ-04 §6-4。対外名称は GOV-02 TBD-14）の **質問 48 問・選択肢・配点・重み・リスクフラグ・通常ロジック・矛盾ルール** を、実装（`src/diagnoses/pro/`）と AI 分析（PRD-05）の入力として確定できる粒度で定義する。無料診断 2 本（PRD-07）から回答を引き継ぎ、重複する問いは有料版で「再確認」として扱う。

本書の状態: 質問文・配点は `Assumed`（事業責任者レビューで確定）。分野・件数・ロジックの骨格は BIZ-04 §12 の `Confirmed` 要件に従う。

---

## 0. 設計方針

| 方針 | 内容 |
| --- | --- |
| 分量 | 選択式 40 問 + 記述式 8 問 = 48 問（BIZ-04 の 40〜60 問の範囲）。企業情報 8 項目は別枠（採点しない） |
| 尺度 | 選択式は 4 段階（0〜3 点）。ai-dx と同じ「0 = 未着手 / 3 = 仕組みとして回っている」の意味に統一し、レベル名も揃える |
| 重み | `weight` 1 または 2。経営判断に直結する問い（責任者の有無・バックアップ・経営数字）を 2 |
| リスクフラグ | `risk_flag`: high / medium / none。低得点（0〜1 点）のときに緊急度へ反映する |
| 回答の負担 | 「分からない」を選べる問いは選択肢 0 に「把握していない」を統合し、要確認フラグを立てる（無料版 ai-dx q5 と同じ考え方）。社内調査が必要な問い（利用システム一覧・費用）は記述式にし、**ヒアリングで補完してよい**と明記する |
| 無料版との関係 | 無料版で答えた問いは初期値として表示し、変更可能。変更されたら `contradictions` 候補（§4 R-11） |
| 言葉 | 専門用語は選択肢内で言い換える（「MFA」→「ログイン時のスマホ確認など二段階の確認」） |

## 3. 通常ロジック（決定的。AI に任せない — BIZ-04 §12-2）

### 3-1. スコア

| 出力 | 算出 |
| --- | --- |
| 質問得点 | `points × weight`（0〜6） |
| 分野スコア（%） | 分野内の質問得点合計 ÷ 分野内の `3 × weight` 合計 × 100。小数第 1 位を四捨五入 |
| 総合スコア（%） | 6 分野の分野スコアの単純平均（分野間の重み付けはしない。分野ごとの問数差を吸収するため） |
| 成熟度レベル | 総合 %: 0-20 → L1 アナログ期 / 21-40 → L2 デジタル移行期 / 41-60 → L3 デジタル定着期 / 61-80 → L4 AI活用期 / 81-100 → L5 AI浸透期（ai-dx と同じ名称） |
| 分野別レベル | 分野スコアに同じ閾値を適用 |
| 改善余地 | `100 − 分野スコア`。大きい順に並べる |

### 3-2. 緊急度

| 条件 | 緊急度 |
| --- | --- |
| `risk = high` の質問で 0 点 | **高** |
| `risk = high` で 1 点、または `risk = medium` で 0 点 | **中** |
| `risk = medium` で 1 点 | 低 |
| それ以外 | — |

緊急度「高」の項目は、AI の優先課題選定に関係なく **レポートの「放置リスク」に必ず載せる**（PRD-05 §6）。

### 3-3. 優先課題候補（8 件）

各選択式質問について `候補スコア = (3 − points) × weight × 緊急度係数（高 2.0 / 中 1.5 / 低 1.2 / — 1.0） × 経営課題係数`。経営課題係数は、S7-T・S8-T の記述にその質問の分野キーワード（§3-4）が含まれれば 1.3、なければ 1.0（単純な語彙一致。AI の判断ではない）。上位 8 件を `priority_candidates` として AI に渡す（PRD-05 §3）。同点は分野順（strategy → process → systems → data → ai → security）→ ID 順。

### 3-4. 分野キーワード（経営課題係数用）

| 分野 | キーワード（部分一致） |
| --- | --- |
| strategy | 方針, 戦略, 目標, 経営, 投資, 責任者 |
| process | 手作業, 紙, FAX, Excel, 二重, 転記, 属人, 手順, 問い合わせ, 書類, 残業, 人手 |
| systems | システム, 連携, 古い, ベンダー, 業者, ソフト, ツール |
| data | 数字, 売上, 在庫, 顧客, 資金, 見え, 集計, データ |
| ai | AI, ChatGPT, 生成, 自動化, チャット |
| security | セキュリティ, バックアップ, パスワード, 退職, ウイルス, 情報漏, 復旧 |

### 3-5. 推奨施策の 4 区分（AI が付ける `category` の判定基準。AI にはこの表を渡す）

| 区分 | 目安 |
| --- | --- |
| 自社でできる（self_service） | ルール決め、棚卸し、手順書作成、既存ツールの設定変更 |
| SaaS で対応（saas） | 汎用クラウドサービスの導入で足りる（会計・勤怠・チャット・顧客管理・バックアップ等） |
| 専門家支援が必要（expert_support） | ルール整備・教育・データ設計・AI 活用の立ち上げなど、進め方に伴走が要るもの |
| システム開発が必要（system_development） | 自社業務に合わせた画面・連携・自動化が要るもの |

「何でもシステム開発へ誘導しない」（BIZ-04 §13）: 4 区分すべてを少なくとも 1 件ずつ含める（PRD-05 §5）。

## 5. 定義データの形（`src/diagnoses/pro/data.ts` と `diagnosis_definitions.definition_json`）

```ts
export interface ProQuestion {
  id: string;             // "S1" … "C9-T"
  area: "strategy" | "process" | "systems" | "data" | "ai" | "security";
  kind: "select" | "text";
  prompt: string;
  options?: { label: string; points: 0 | 1 | 2 | 3 }[];   // select のみ 4 件
  weight?: 1 | 2;                                          // select のみ
  riskFlag?: "high" | "medium" | "none";                   // select のみ
  freeRef?: { slug: "business" | "ai-dx"; questionId: string; map: number[] } | null; // 無料版の選択肢 → 有料版の初期選択肢
  required: boolean;      // 記述式は false
  unknownIsZero?: boolean; // 選択肢 0 が「把握していない」を含む問い（A1 / C2 / C3 / Y1 / PF5）。要確認フラグ
}

export interface ProDefinition {
  slug: "pro";
  version: number;        // 1 から。変更のたびに +1（diagnosis_definitions に公開時スナップショット）
  areas: { id: string; name: string }[];
  levels: { level: 1 | 2 | 3 | 4 | 5; name: string; min: number; max: number }[];
  questions: ProQuestion[];
  contradictionRules: { id: string; when: string; message: string }[]; // when は純関数側で実装し、id で対応付ける
  areaKeywords: Record<string, string[]>;
}
```

- 判定（§3）と矛盾検出（§4）は `src/diagnoses/pro/scoring.ts` の純関数に置き、`apps/admin` の Service からも同じ関数を呼ぶ（DEV-11 §4-3: Phase 3 で `packages/diagnosis` へ移す判断）。無料診断 2 本とはコードを共有しない（`CLAUDE.md`）。
- `freeRef.map` は無料版の選択肢番号 → 有料版の選択肢番号の対応表（例: `B-q7` の 4 択を P1 の 4 択へ `[0, 1, 3, 2]` のように写す。「該当なし」は `null`）。

## 6. 回答画面（SCR-23）の要件（PRD-04 §4-6 の補足）

- 分野ごとに 1 ページ（6 ステップ）。各ページで途中保存（`PUT …/answers/`）。ブラウザを閉じても再開できる。
- 無料版から引き継いだ問いは「無料診断でのご回答: ○○」を選択肢の下に表示し、初期選択済みにする。
- 記述式は任意。「分からなければ空欄で構いません」を明記。
- 全必須問（選択式 40 問 + 企業情報 PF1〜PF3・PF7・PF8）が埋まると提出ボタンが有効になる。
- 所要時間の目安を最初に表示する（20〜30 分。`Assumed`、モニターで実測）。
