# 07-diagnosis-free-redesign.md — 無料診断 再設計案

## このセクションの目的

無料診断 2 本を **捨てずに点検・再設計**する案を、質問・選択肢・配点・判定・結果文章・CTA まで具体的に提示する。承認前にコードへ反映しない。既存 URL・結果タイプ ID・レベル ID・既存デザインの基本方針・判定ロジックの骨格は維持する（BIZ-04 §7 の原則）。

本書の記述状態: 質問案・配点案は `Assumed`（承認と実装時シミュレーションで確定）。維持と明記した項目は現行どおり（`Confirmed` 相当）。

### 1-3. 判定方法（案）

1. q1〜q9 の回答から 9 タイプの **生点** を合計する（現行と同じ）。
2. 各タイプの生点を、そのタイプの到達可能最大点で割った **課題度（0〜100%）** を求める。「※該当なし」を選んだタイプは判定対象から除外する（課題度を計算しない）。
3. 課題度の最大が 0（全タイプ 0 点）なら **Z（健全経営型）**。
4. 課題度が最大のタイプが 1 つならそれが主タイプ。同点なら現行と同じく **q0 の関心タイプを優先し、次に固定順 `[B, A, I, E, D, C, F, G, H]`** で決める。
5. 主タイプを除いた最大課題度のタイプ（0% 超）を **副次タイプ** とする。
6. 課題度 0% のタイプ（該当なしを除く）を **強み** とする。3 つを上限に、固定順で表示する。
7. 主タイプに加点した回答を **判定理由** として最大 3 件並べる（点の大きい順、同点は質問順）。

割合比較を採る理由: 質問数を増やさずにタイプ間の公平性を担保できる唯一の決定的な方法であり、レーダーチャートの目盛りも「%」に統一できる。代替案（配点の再調整のみで揃える）は選択肢の意味を歪めるか 3 点の選択肢を増やすことになる。どちらを採るかは GOV-02 TBD-21。

**結果 URL（v2）**: `/diagnosis/business/result/<主タイプ>/?v=2&second=<副次>&concern=<1〜7>&s=<A〜I の生点 "." 区切り>&na=<該当なしタイプ小文字を "." 区切り>`
`v` が無い URL は v1 として現行の描画を維持する（PRD-06 §4）。`s` の要素順は A〜I 固定で v1 と同じ。

| 選択肢 | `<div role="radiogroup" aria-labelledby=<h2>>` + `<button role="radio" aria-checked>` に変更するか、現行 `aria-pressed` を維持するかは実装時に `fixing-accessibility` スキルで判断 |
| ぼかし | 廃止により `aria-hidden` の非対称（P-10）は解消 |
| 動き | 既存の `diagnosis-reveal` アニメーションは `prefers-reduced-motion` で無効化する |
| URL | 結果 URL の追加パラメータは全て任意。`v` 無しの URL は v1 として現行描画。タイプ・軸の **追加・並べ替えは行わない**（`s` の互換性 — PRD-06 §4） |
| sitemap | 結果ページはこれまでどおり sitemap 未掲載・index 可。noindex 化の要否は GOV-02 TBD-23 |

## 6. 有料版へ移す候補（無料版から意図的に外す設問）

BIZ-04 §7-3 の方針。以下は無料版に **入れない**。

| 領域 | 有料版で聞く内容 | 無料版で聞かない理由 |
| --- | --- | --- |
| 利用システム | 利用中のシステム・SaaS の一覧、契約・費用、連携状況 | 社内調査が必要 |
| IT 費用・予算 | 年間 IT 費用、投資予算、希望時期 | 経営判断の機微。匿名では答えられない |
| セキュリティ | アカウント管理、多要素認証、バックアップ、退職者対応 | 専門用語が多く、誤答しやすい |
| 組織体制 | IT 担当者の有無・役割、決裁者、外部ベンダー | 記述が必要 |
| 経営戦略 | 経営課題と IT 投資のつながり、KPI | ヒアリング向き |
| 個別業務量 | 業務ごとの件数・時間 | 無料版は「最初の一歩」で自分で測ってもらう |
| 記述式 | 困っていること、期待 | 匿名 10 問の完了率を守る |
