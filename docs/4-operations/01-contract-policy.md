# 01-contract-policy.md — 契約ポリシーテンプレート

## このセクションの目的

Web サイトの受託制作 + 運用保守契約における利用規約・SLA・契約変更・データ取扱い・損害賠償・免責を定義する。本テンプレートは 00_README §0-1 の**パターン A**（コンテンツ主体サイト + 軽量な管理画面）を前提とし、収益モデルは受託制作（初期構築費）+ 月額保守（BIZ-03 参照）である。Organization 単位のサブスクリプション契約は本テンプレートの対象外。**法務確認必須** 項目を多数含むため、最終確定前に弁護士レビューを受けること。

## 0-H. ハイブリッド編集ガイド（要点）

- 推奨モード: Human-first または Hybrid
- 人間確認必須: 法務表現、補償条件、データ返却・削除方針

## 2. 契約の主要条項

### 2-1. 提供サービスの定義

**該当なし。** naturaling.jp は自社サイトであり、提供サービスとして定義される対象ではない。

### 2-2. 発注者の責任

- 提供する原稿・画像等のコンテンツが正確であり、第三者の著作権・商標権・プライバシーを侵害しないこと
- 管理画面（`admin` / `editor`）のアカウント情報（ID / パスワード）の管理責任
- 契約範囲外の要望は都度見積もりの対象となることの了承

### 2-3. 知的財産権

| 区分 | 取扱い |
| --- | --- |
| サイト本体（デザイン・コード・テンプレート） | 検収完了後、契約書に定める範囲でクライアントに譲渡または利用許諾（要法務確認） |
| クライアント提供コンテンツ（Post/Page/Media） | クライアントが著作権保持。サイト掲載のための利用許諾を受ける |
| 自社の既存テンプレート・ノウハウ（本テンプレート自体） | 自社が保持。個別案件への利用許諾のみ行う |
| AI 生成物（採用時） | クライアントが独占的利用権を取得（利用規約に明記、要法務確認） |

### 2-4. データの取扱い

**本節は実態を記載する**（本書で数少ない該当あり）。詳細は DEV-02 §8 が正本。

| データ | 取扱い | 外部への提供先 |
| --- | --- | --- |
| お問い合わせの入力内容（氏名・メール・会社名・電話・本文） | **DB に保存しない。**Resend 経由でメール送信され、`CONTACT_NOTIFY_TO` の受信箱と送信者本人の受信箱にのみ残る | Resend（送信委託）、Cloudflare Turnstile（ボット判定のため送信元 IP を送信） |
| アクセス解析データ | サイト改善目的 | Google（GA4、測定 ID `G-74BTEE20D1`） |
| AdminUser 情報 | サービス提供目的のみ。**現在アカウント発行なし** | なし |
| Media / 操作ログ | **未使用**（R2・`activity_log` ともに稼働していない） | — |
| 決済情報・AI プロンプト | **取得しない**（軽量 EC・AI 機能ともに不採用） | — |

> **要確認**: 保管期限の主体がアプリからメールボックス運用に移っている点が、`/privacy-policy/` の記載と整合しているか（GOV-02 TBD-07）。

### 2-5. LLM 利用への同意（AI 機能採用時のみ）

**該当なし。** AI 機能は不採用で、LLM に送信されるデータは存在しない（PRD-05）。

### 2-6. 禁止事項

- 違法行為への利用、第三者の権利侵害
- サイトを通じた第三者へのスパム的な大量送信・自動収集
- リバースエンジニアリング
- AI 出力の悪用（プロンプトインジェクション等、採用時）

## 3. SLA（サービスレベル）

### 3-1. 稼働率

可用性の数値目標は **PRD-02 §5-2 を正本** とし、本書では値を再掲しない。SLA として提示する際も PRD-02 §5-2 の目標値をそのまま用いる。

**契約上の SLA は存在しない**（自社サイト）。稼働率の目標値そのものが未設定（PRD-02 §5-2 が **要記入**）。

なお公開ページは Cloudflare の静的アセットとして配信されるため、可用性は実質 Cloudflare のエッジに依存する。Worker が落ちても影響を受けるのはお問い合わせ送信のみ。

## 8. 承認・公開ルール

<!-- TEMPLATE: 本節はクライアント承認フローが必要な場合に使用する。自社運営サイトで承認フローが不要な場合は削除してよい -->

### 8-1. 承認不要の変更（例外）

自社サイトのため対外的な承認フローは無いが、**URL に影響する変更だけは別扱い**とする。以下は通常のレビューのみで進めてよい：

- 誤字脱字・軽微な文言修正
- 既存画像の差し替え
- お知らせの新規公開（`packages/content/news/` へのファイル追加 + `public/sitemap.xml` への追記）

### 8-2. 最終承認必須事項

以下は必ず承認の対象とする：

- **公開済み URL の変更・削除**（お知らせのファイル名変更を含む）。インデックス済みのため SEO の後退に直結する（GOV-01 D-002・D-008）
- `public/_redirects` の変更（旧サイトからの 301 が 9 本入っている）
- 会社情報・法的表記（`/company/`・`/privacy-policy/`）の変更
- 事業内容・サービス紹介の大幅な変更
- ページの新規追加（`public/sitemap.xml` への追記漏れが起きやすい）

### 8-3. 本番公開条件（チェックリスト形式）

移行後の構成を本番へ切り替える際のチェックリスト。**2026-09-10 時点でいずれも未完了**（GOV-02 §2-5、README「Remaining setup」と対応）。

- [ ] Cloudflare リソース（D1 / R2 / KV）を作成し、両アプリの `wrangler.jsonc` の `replace-with-*` を置換した（`database_id` は両アプリで一致）
- [ ] カスタムドメイン（`naturaling.jp` / `www.naturaling.jp`）を `routes` に設定した
- [ ] `RESEND_API_KEY` と `TURNSTILE_SECRET_KEY` を Workers Secrets に登録した
- [ ] **`PUBLIC_TURNSTILE_SITE_KEY` をビルド変数に設定した** — 未設定でもフォームは動くため、テストキーのまま公開してしまう事故が起きやすい
- [ ] Resend のドメイン認証（DKIM 等の DNS レコード）を通した
- [ ] `main` ブランチを作成し、Cloudflare Workers Builds（Root directory / Build Watch Paths / Deploy command）を設定した
- [ ] `pnpm db:generate` を実行し、生成されたマイグレーションをコミットした（CI は自前で生成するため、CI が緑でもコミット済みとは限らない）
- [ ] 本番 URL で `_redirects` の 301 が 9 本とも効くことを確認した
- [ ] 主要 URL が移行前と一致していることを確認した（`public/sitemap.xml` の 23 件）
- [ ] お問い合わせフォームから実際に送信し、通知メールと自動返信の両方が届くことを確認した
